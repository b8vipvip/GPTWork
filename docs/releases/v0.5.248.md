# GPTWork v0.5.248

## 实机证据

v0.5.247 的单次 Astra 测试 `15564.1191` 在已存在会话中真实改写并转发 `gpt-6-astra-wm`，HTTP 200 后约 2.98 秒由 Chrome 报告 `net::ERR_ABORTED` / `canceled=true`。已捕获 8,979 字节 SSE，其中 15 个结构化 JSON 事件，`[DONE]` 已出现，但助手状态仍为 `in_progress`，没有观察到 `finished_successfully` 或流内明确错误。目标标签页在调试过程中还观察到 6 次 conversation-detail HTTP 404。上述证据均不能证明 Astra 真实执行或判定谁触发了请求取消。

同轮运行时 JSONL 更重要的普通模型对照：已有会话中的 `gpt-6-thinking` 正式请求 `15564.1169` 也在 HTTP 200 后报告了 `Network.loadingFailed`、`net::ERR_ABORTED`。原有 ordinary-model 验证器给出了 `verified`（模型身份匹配），但缺乏普通请求的 SSE 应用完成/错误分类，因此不能仅据此声称普通请求传输成功。这两类证据必须独立呈现。

## 本版变更

- 为**正常官方 ChatGPT 请求**新增与 Astra 探针完全相同的、只读的 SSE 分类诊断，在普通请求有实际响应流时记录 `normal_conversation_sse_baseline_observed`。
- 记录规范化模型标识、HTTP 状态、正式 POST 是否正常完成、Chrome 是否报告 `net::ERR_ABORTED`、SSE `[DONE]`、助手 `finished_successfully`、应用错误信号、JSON/数据段计数、捕获字节与是否观察到下游流移交。避免把“模型身份匹配”混同为“会话成功结束”。
- 严格不导出普通请求的正文、提示词、任意流数据或错误消息；对未知网络错误仅记录 `other_network_error`，不暴露错误文本。
- 共享现有 `astra-debug-sse.js` 的分析器，不新增请求拦截、重新发送、模型决策或后端能力假设。若正常请求未发生、没有原始 SSE 或来源不匹配，则不产生虚假的对照结论。
- 增加回归测试覆盖正常请求中断、正常结束、流内错误、安全脱敏与零请求变更。

## 验证方式

安装后，在**同一个已有 ChatGPT 会话**先手动发送一次普通 `GPT-6` 消息，再使用调试工具发送一次单次 Astra 消息。完成观察后导出两份文件：运行时 JSONL、Astra 调试 JSON。对照 `normal_conversation_sse_baseline_observed` 与 `astra_debug_response_model_evidence` 事件的 SSE 助手结束状态、`[DONE]`、网络终态、HTTP，以及相同会话里反复出现的 HTTP 404。

> 本版只修复 **正常请求缺乏同口径 SSE 证据** 的诊断缺陷，未证明 `net::ERR_ABORTED` 的最终触发方，也不宣称已修复 ChatGPT 的网络连接或服务端模型兼容性。
