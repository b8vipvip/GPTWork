# GPTWork v0.5.244

## Astra 单次真实请求：中断流证据保全

v0.5.243 已能将固定调试请求的顶层模型从 `gpt-6-thinking` 改写为 `gpt-6-astra-wm` 并获得 HTTP 200。但一轮实机测试中，浏览器在收到部分 SSE 数据后报告 `net::ERR_ABORTED`。原调试探针先在 `conversation_response_failed` 结束，随后才到达的模型证据被漏记。

本次修复：

- 失败终态不再提前销毁探针；先记录异步 SSE 解码后的响应模型、字段、默认模型、流阶段，再结束。无后续证据时保留失败终态，不改写成超时。
- 新聊天的 `/` → `/c/local-chatgpt` → `/c/:id` 导航保留同一正式请求的转发模型和验证策略；真实会话间跳转继续隔离。
- 页面回复观察允许上述新聊天导航，仍拒绝无关会话跳转。
- 只有完整成功的响应和精确 Astra 模型字段才能确认 Astra。中断流、家族级 `gpt-6`、默认模型 `gpt-6-astra` 均不构成 Astra 实际执行的证明。
- 调试工具页新增网络错误、流证据阶段、默认模型元数据、回复观察原因，便于导出与核对。
- 新增回归测试覆盖中断流、家族级模型证据、新聊天两次路由迁移及诊断终态顺序。

## 实机验证

更新后建议先选一个**已有会话**运行一次固定 Astra 测试，避免新聊天创建/导航干扰；随后可在**新聊天**再次运行对比。导出调试结果 JSON 和运行时 JSONL，按同一 `requestId` 检查 `astra_debug_request_forwarded`、`astra_debug_response_model_evidence`、HTTP/SSE 终态与 `resolved_model_slug`。

**边界：** 本版修复诊断关联与证据保全，未证明 ChatGPT 服务端实际以 Astra 执行，也不能单凭 HTTP 200 判断模型已被接受。网络 `ERR_ABORTED` 的最终触发方仍需实机对照确认。
