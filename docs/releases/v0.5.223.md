The v0.5.222 runtime log contains an actual formal request in tab **124173997** at **02:14:01.929Z**, CDP request ID **15316.437**, model **gpt-6-thinking**, reasoning **high**. The tab's monitor was detached at **02:14:02.265Z** and again at **02:14:08.954Z**. No matching response evidence was subsequently recorded. The performance telemetry also showed `responseCaptureTabs: 0` during the ongoing generation. This establishes capture discontinuity, *not* a backend model mismatch.

## Single-owner lifecycle corrections

- Keep the existing CDP session attached during the `loading` phase of an enabled ChatGPT tab. `detach()` deletes tracked requests/streams; page loading is not an explicit stop decision.
- Preserve the existing ordinary request and response state during the exact one-way ChatGPT home (`/`) to first conversation (`/c/:id`) navigation, provided a formal request was captured within the existing 15-minute request retention bound.
- Other conversation switches and stale home requests still reset state and may not inherit old response proof.
- A failed passive page observation no longer marks its fingerprint as delivered, allowing later page events to retry.
