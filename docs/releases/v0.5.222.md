# GPTWork v0.5.222 — Discovery-only ChatGPT page selection

## Field evidence
- Normal ChatGPT picker showed GPT-6 checked, while GPTWork displayed requested `gpt-6-thinking` and a response model still waiting for authoritative metadata.
- Client logs show a formal `gpt-6-thinking` request with High effort in ChatGPT tab `124173819`. The GPTWork-project tab `124173918` instead logged picker pointer activity, but no corresponding completed formal request-to-served-response chain. These are separate tabs; the request evidence cannot be attributed to the screenshot's turn without more data.
- A request-model field does **not** prove that ChatGPT executed an ensemble of GPT-6, GPT-6 Thinking and GPT-6 Sol. Only explicit served/resolved/used network response metadata can be reported as backend-confirmed; ChatGPT's private internal routing is not observable through this plugin.

## Changes
- Remove automatic page-alignment timers and model/effort clicks during ordinary Chat.
- Require an active, explicit discovery task in both the content runtime and background CDP authorization before trusted or synthetic UI input.
- Reject stale UI clicks after a discovery task ends. Honor none of the old remote/local `autoAlignSelection` values; this compatibility setting is now inert.
- On a completed response with no authoritative served-model metadata, record an unverified outcome rather than leaving "waiting" forever. Preserve raw stream diagnostics and let a downstream stream replace that outcome if it later reports the real served model. An initial stream handoff is not prematurely finalized.
- No fallback to the request model or generic assistant `model_slug` for response proof.
