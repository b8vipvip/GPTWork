# GPTWork v0.5.253

## 修复：响应超时跟随真实流活动刷新

- 修复长时间持续输出的响应可能被 120 秒响应证据闹钟误判为超时的问题。
- Network.dataReceived 收到与当前正式请求关联的 HTTP/SSE 下游数据时，记录最后活动时间；即使 CDP 只提供字节计数、没有可解析的响应正文，也能正确刷新空闲计时。
- WebSocket 已关联到响应 handoff 后，后续服务端帧即使不再重复携带初始 topic 标记，也继续提供该请求的传输活动证据。
- 活动记录严格绑定初始请求 ID，只刷新当前处于 waiting 状态的同一请求；新请求会重置旧流状态，旧请求迟到的回调不能延长新请求的等待期限。
- 字节活动仅用于响应超时恢复，不会生成模型 ID、增加下游模型证据计数或把未确认响应提升为已验证。
- 修复 GPTAuto Observer 对延迟 synchronize 事件的处理：先读取 GitHub 当前 PR head，忽略过期事件，并在每次取消旧工作流前再次核对 live head，避免取消当前提交的 CI。
- 同步 README 的正式版本信息，并补充请求关联、SSE/WebSocket 活动和 GPTAuto 过期 head 防护的回归测试。

## 验证与发布

- PR CI 与合并后的 main CI 均通过；扩展测试套件 992 项通过、0 项失败。
- Store Package、Private Core Boundary、Actions Policy Check、GPTAuto Observer/Reconcile 和 Release 工作流成功。
- 正式版 v0.5.253 已发布，包含 Windows 安装程序 `GPTWorkSetup-x64.exe` 和 Linux 安装包 `GPTWork_0.5.253_amd64.deb`。
- 本版只将真实、请求关联的流活动用于等待超时管理；传输活动不等同于模型身份或响应内容验证。
