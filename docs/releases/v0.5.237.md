# GPTWork v0.5.237 — Response mismatch is warning-only

- A confirmed served-model mismatch (`model_not_allowed`) no longer blocks the ChatGPT composer in strict mode. The same behavior applies in warn mode.
- Preserve the real response-model evidence, policy snapshot, `mismatch` verdict, and request interception/rewrite. A mismatch is **not** a successful verification.
- A newer mismatch takes precedence over earlier successful auto-verification when displaying status.
- Popup, page indicator, badge, and strict-mode description explicitly communicate that mismatches are warnings, not send blocks.
- Regression tests cover current and historical lock epochs, model aliases, strict/warn settings, and auto-verification precedence.
