# GPTWork v0.5.247

## 本轮实机证据

v0.5.246 测试在已存在会话中执行，Astra 调试请求 `15564.1051` 实际由 `gpt-6-thinking` 改写转发为 `gpt-6-astra-wm`，约 3.25 秒后浏览器报告 `Network.loadingFailed`、`canceled=true`、`net::ERR_ABORTED`，虽然已收到 HTTP 200 与部分 SSE 数据的结束标记。响应 `resolved_model_slug=gpt-6` 仅为 GPT-6 家族标识；`default_model_slug=gpt-6-astra` 为默认模型元数据。没有证据证明 Astra 实际完成回复。

此轮没有观测到新聊天页面导航，排除了“本次失败必然由新聊天创建跳转触发”的解释。同步运行日志显示多个 ChatGPT 标签页的会话详情 GET 反复返回 404；不能仅凭这一现象断定该 404 与 Astra 失败存在因果关联。

## 改进

- 分开记录 SSE 传输结束标记（`[DONE]` 或 `message_stream_complete`）、助手消息出现与助手 `finished_successfully` 状态、流内明确错误事件以及 Chrome 的 `Network.loadingFailed`。
- 流内错误与 `[DONE]` 可以同时存在；未观察到结构化错误信号不代表服务端不存在其他错误。完成的流式消息也不能覆盖 Chrome 上报的浏览器取消终态或证明 Astra 执行。
- 只导出 SSE 数据段/JSON 对象计数、允许枚举的助手状态、是否出现错误/助手最终状态、网络捕获字节数。不会导出原始 SSE、错误字符串、提示词、身份凭证或任意回复正文。
- 统计所选 ChatGPT 标签页在调试期间的会话详情 HTTP 404 次数，帮助与其他标签页及普通模型请求对照。计数本身不构成根因证明。
- 调试工具显示这些结构化字段，新增回归测试覆盖 SSE `[DONE]` 与错误共存、助手最终状态、部分/超限流以及 CDP 网络中断与模型确认独立判定。

## 下一轮验证

建议先在同一已有会话中进行**普通官方模型的手动提示词请求**，确认页面是否成功显示回复及是否仍反复出现 404；随后运行一次固定 Astra 测试。分别导出完整运行时 JSONL 和 Astra JSON，比较网络取消、流内应用错误信号、助手最终状态和 HTTP 404。

**边界：** 此版本针对当前真实证据增强诊断，不修改模型锁定或把中断流伪装成成功。HTTP 200/SSE `[DONE]` 仍不代表 `gpt-6-astra-wm` 模型已经执行。浏览器取消的最终触发方仍需基于下一轮对照验证。
