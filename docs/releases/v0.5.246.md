# GPTWork v0.5.246

## 实机问题和证据

v0.5.245 的固定 Astra 调试请求 `15564.849` 已从 `gpt-6-thinking` 实际改写并转发为 `gpt-6-astra-wm`；HTTP 200，SSE 结束标记可见，同时 `Network.loadingFailed` 报告 `net::ERR_ABORTED`，解析出的 `resolved_model_slug=gpt-6` 仅是 GPT-6 家族级证据，`default_model_slug=gpt-6-astra` 不能证明实际服务模型。页面回复观察单独报告 `conversation_navigated`，未证实 Astra 实际执行。

旧版诊断还有一处竞态：网络失败证据一经解析，探针就结束并移除，可能丢掉随后才返回的页面助手回复结果。浏览器在“新聊天”切换时，页面回复观察只能给出模糊的导航失败原因，无法判断是正常临时路由还是不相关的页面跳转。

## 变更

- **同一观测的单一终态闭环**：探针仅在网络证据和独立页面回复观察都结束后归档；浏览器网络失败始终保留失败状态，即使后来观察到页面回复也不能冒充成功的 Astra 传输。若内容脚本中断，明确记录 `content_message_failed`；180 秒兜底保留真实失败而不是伪造成功。
- **保留原始网络取消证据**：记录 CDP `canceled` 标志与网络耗时，并区分初始正式请求与后续 downstream 协议事件，避免下游事件覆盖初始请求的真实终态。
- **安全的 SPA 路由轨迹**：页面观察允许首次新聊天在 `/`、`/c/local-chatgpt` 与最终真实会话之间做有限跳转（包括末尾斜杠和未建立最终会话前的返回主页），一旦进入真实会话后仍拒绝切换到不同会话。仅导出 `new_chat`、`placeholder`、`conversation`、`other` 类别和跳转次数，不导出具体会话 ID 或用户正文。
- **诊断 UI**：显示浏览器取消标志、网络耗时、页面导航事件与页面观察状态。网络失败后页面观察未结束时不允许重复启动新的调试请求，避免混淆。
- 增加自动化测试覆盖 SSE 已结束但 CDP 取消的状态、网络/页面观察竞态、SPA 有限跳转、跨会话拒绝与诊断脱敏。

## 实机对照验证

建议 **先在已存在的会话** 测试，再在 **新聊天** 测试，分别导出最新的 Astra JSON 及运行时 JSONL。按每次不同 `requestId` 比对：`Fetch.continueRequest` 真实模型、HTTP、SSE、`Network.loadingFailed.canceled`、导航阶段和助手回复。

> 本版本加强可证伪性与观测生命周期，**没有证据证明**仅靠上述修复能够消除 ChatGPT 或浏览器发出的 `net::ERR_ABORTED`。正常用户请求也曾出现相同错误，因此仍需对照实验确定是否与 Astra 改写相关。HTTP 200、SSE `[DONE]`、默认模型元数据均不是 Astra 真实执行证明。
