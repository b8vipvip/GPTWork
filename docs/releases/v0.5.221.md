# GPTWork v0.5.221 — DOM listener lifecycle performance fix

## Runtime evidence
- v0.5.220 client samples showed content lifecycle `domEventListeners` rising above 420,000, accompanied by significant page long tasks and event-loop lag.
- The content supervisor used linear `[...eventListeners].find` for every add/remove and kept registered DOM targets alive through strong references.
- Separate upstream failures (`Failed to fetch`, HTTP 502, `net::ERR_CONNECTION_CLOSED`) are *not* claimed as resolved by this patch.

## Changes
- Use per-target weak listener identity indexes; avoid quadratic scans under heavy DOM churn.
- Avoid retaining detached DOM nodes in the shutdown registry through strong references.
- Respect capture, duplicate, once, and AbortSignal listener semantics.
- Skip per-listener stack tracing outside an explicit diagnostic capture.
- Add deterministic listener regression coverage and preserve content-runtime teardown.

## Validation and remaining risks
- Automated extension tests, native builds, package checks, and private distribution checks must pass before release.
- Real-world Chrome/Edge heap profiling and a renewed v0.5.221 runtime sample remain necessary to prove reduced jank on the user's workload.
- No changes to ChatGPT model-selection truth or response-verification rules.
