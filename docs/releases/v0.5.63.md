# GPTWork v0.5.63

## Fixes

- Fix post-update recovery race where the new extension worker could inherit the temporary Master=OFF state and leave Native Core/request locking offline until a manual extension reload.
- Reconnect through the background lifecycle authority after restoring Master, waiting for any in-flight initialization to settle first.
- Make manual reconnect wait for the current initialization instead of reusing stale `master_disabled` state.
- Improve **下载并安装本地核心 / Download installer**: check the already-installed Native Core first; if it exists, automatically reload GPTWork and recover the connection instead of downloading another installer.
- Only open the formal installer page when the local Core is actually unavailable.
- Clear the stale update-failure state after the installed extension/Core/runtime have recovered successfully.
- Add regression coverage for updater recovery and Core repair behavior.
