# GPTWork v0.5.245

## Astra 调试发送失败：输入框定位与标签页身份可视化

v0.5.244 实机调试 JSON 连续三次记录 `ChatGPT composer not found / 未找到 ChatGPT 输入框`，相同的目标标签页为 `124175961`；未触发 Fetch 转发，无 HTTP、SSE、请求 ID。这不是模型被服务端拒绝，而是发送前的页面控件识别失败。

本次修复：

- 新增只读、单一来源的 ChatGPT 输入框定位服务，由调试发送器和发送按钮兼容器共同使用。先识别现有 `#prompt-textarea` 等明确标识，找不到时仅在聊天主区域的表单/Composer 容器寻找可见、可编辑的输入框；支持 `contenteditable="plaintext-only"` 等新版结构。多个不明确输入框时拒绝猜测，不会对搜索框、侧边栏或弹窗写入内容。
- 明确由用户触发的 Astra 调试增加页面输入框就绪等待；若仍找不到，在原错误中附加 `ready`、`visible`、`mainForms`、`visibleEditable`、`chatHinted` 等结构化统计，不读取/导出用户草稿。
- 调试工具“目标 ChatGPT 标签页”下拉列表增加 Chrome 窗口 ID、标签顺序、页面标题和标签 ID，显示选中标签详细信息，并加入“定位标签页（不发送请求）”。这项操作只切换到对应标签，不发消息。
- 调试结果只显示选中标签页的历史/活动记录，不再误用其他标签页的旧记录。
- 新增回归测试覆盖新版编辑器、侧边栏排除、含糊控件拒绝、统一选择器与标签定位。

## 实机核验

1. 更新并打开 ChatGPT，确认对应标签的输入框已出现。
2. 在 GPTWork 调试工具中先选中目标标签，然后点击“定位标签页”，核实跳转到正确窗口。
3. 返回调试工具再按“发送单次 Astra 测试请求”；会将固定测试文本真实发送至该 ChatGPT 会话，可能消耗账户额度。
4. 若失败，导出 Astra JSON 及运行时 JSONL，并提供新版 `composer not found (DOM: ...)` 结构计数。

本版修复目标是**发送阶段的页面输入框识别与标签页身份**。不声称已证明 `gpt-6-astra-wm` 真正被服务端执行。HTTP 200、请求改写、默认模型字段与精确模型服务端证明保持区分。
