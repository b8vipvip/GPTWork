# GPTWork v0.5.249

## 实机复现（v0.5.248）

同一已存在的 ChatGPT 会话及同一标签页：

- 普通 GPT-6 请求 `15564.1295`：`gpt-6-thinking`，HTTP 200，`net::ERR_ABORTED`、`canceled=true`，6,117 ms；解析到相同的 `resolved_model_slug=gpt-6-thinking`，普通锁验证器记录 `verified`。后者仅说明**模型字段匹配**，并不能证明传输正常结束。
- Astra 调试请求 `15564.1323`：从 `gpt-6-thinking` 改写转发 `gpt-6-astra-wm`，HTTP 200，5,580 ms 后 `net::ERR_ABORTED`、`canceled=true`；8,985 字节 SSE，17 个数据段、15 个 JSON 对象、`data:[DONE]`，助手消息仅 `in_progress`，没有检测到应用错误事件或 `finished_successfully`，页面回复观察超时。
- Astra 调试窗口内同一会话详情请求观察到 HTTP 404 共 8 次；仍不能凭此断言取消与 Astra 模型 ID 存在因果关系。
- **新增诊断缺陷：** v0.5.248 增加的 `normal_conversation_sse_baseline_observed` 事件没有出现在普通请求的实机运行时日志中，尽管普通请求的 HTTP 200 / 浏览器取消 / 响应模型解析被记录。

## 本版修复

- `normalChatSseBaseline` 不再因为普通请求缺少可供观察的原始 SSE 缓冲区，就静默返回 `null`；只要是已识别的普通正式初始对话响应，就保留 requestId、规范化网络错误、HTTP、`loadingFailed`、捕获字节及模型字段。
- 新增 `sseEvidenceAvailable`、`sseUnavailableReason` 和 `networkTerminal`：当没有原始 SSE 时，助手最终状态、应用错误信号、`[DONE]` 和事件计数均明确为 **`null`（未知）**，而不是虚构 `false` 或 0。
- 复用现有的唯一 SSE 分类器，**不修改**正式请求发送、模型决策、CDP 拦截或 ChatGPT 页面状态。仍然只记录安全的结构化证据，不记录原始 SSE、错误正文或用户聊天内容。
- 回归测试覆盖含有响应模型字段但无法提供原始 SSE 的普通中断请求，以及真实 SSE 可读取的情形。

## 下一轮验证

用户升级 v0.5.249 后，在同一已有 ChatGPT 会话手动发送正常 GPT-6 请求，再执行一次 Astra 调试；导出运行时 JSONL 和 Astra 调试 JSON。普通模型即使流数据不可用，也应出现一条 `normal_conversation_sse_baseline_observed`，其中 `sseEvidenceAvailable=false` 和未知的 SSE 终态能揭示对照数据缺口；若数据可用，则直接对照两个请求的 `sseAssistantFinalSeen`、`sseApplicationErrorSeen`、`networkTerminal`。

**证据边界：** 本版修复诊断静默缺失，尚未找到 Chrome `ERR_ABORTED` 的可靠触发方，也未证明 Astra 真正执行。不能把 HTTP 200、SSE `[DONE]` 或家族级模型标识当作 Astra 执行证明。
