# GPTWork v0.5.234 — Strict lock state and Fetch/Network correlation

## Observed incident (2026-10-15 21:19–21:26 +08:00)

- 21:19:18: intercepted formal request: page transport `gpt-6-thinking`, selected lock `gpt-5.6-sol`, forwarded transport `gpt-5.6-sol-wm`.
- 21:19:19: same Network request ID `1768.11467` recorded the original `gpt-6-thinking` with `forwardedFetchRequestId: null`, losing the terminal Fetch correlation.
- 21:19:54: response metadata resolved `gpt-6`, with reasoning not exposed; verification under the original Sol lock correctly recorded a model mismatch. The SSE was aborted.
- 21:25: multiple new sends were blocked by the old mismatch while the popup showed a newer GPT-6 lock and Picker A selected GPT-6.

The old response remains a real, auditable mismatch **for the original Sol request**; it must not block future turns under a changed GPT-6 lock. A missing response reasoning level is never fabricated or treated as confirmed High.

## Fixes

- Make the canonical `policy.lockedModels` the only runtime model-lock selection authority. The legacy `gptworkModelLockSelection` key is retained for UI/migration compatibility but can no longer override the policy and leave the interceptor stuck on an old model.
- Strict guard now compares the previous request's immutable lock snapshot to the currently effective tab lock. When they differ, the old mismatch is historical, sending is allowed under the new lock, and the next formal request is still intercepted and verified.
- Popup and floating status distinguish the historical mismatch from the current lock; raw served-model evidence remains unchanged and reasoning stays unknown if not exposed.
- Add a bounded, tab/request-ID-scoped ledger of successful Fetch.continueRequest decisions. It survives a / → /c/:id state reset and correlates the actual forwarded model to the matching Network request, without cross-tab or cross-request leakage.
- Add regression tests replaying the supplied timestamps, lock change, missing reasoning, and Fetch/Network ID race.

## Scope

No policy weakening for a mismatch on the current request under an unchanged lock. No fabricated reasoning metadata. This release cannot guarantee ChatGPT will honor an unsupported transport ID; response evidence remains the source of truth.
