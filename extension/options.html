锁定模型 Locked models

可多选。正式聊天 POST 发出前，GPTWork 会检查顶层 model；若当前模型不在允许列表，则改写为第一个锁定模型的已知传输标识。

只有正式聊天请求或响应元数据确认的新模型才会加入“自动识别 / Discovered”；页面 DOM 文本只作为辅助观察，不会单独永久入库。新模型首次加入自动识别列表时会自动勾选并立即加入锁定策略；之后你仍可手动取消勾选并保存，GPTWork 不会因后续重复证据把它再次强制启用。

允许的推理强度 Allowed reasoning levels

若正式请求顶层已经存在可识别的推理强度字段，GPTWork 会把不允许的值改为优先推理强度；不会凭空添加网页当前没有发送的字段。

响应确认（可选） Response verification

请求锁定本身也需要 Chrome/Edge 的“调试程序”权限。打开同一标签页的 DevTools 可能抢占调试连接；此时 GPTWork 会告警，但不会把日常聊天卡死。

The request interceptor also uses the browser debugger permission. DevTools may detach GPTWork from the same tab; GPTWork fails open with a warning.

处理模式 Enforcement mode

请求锁定优先保证正常聊天。无论提醒或强制模式，响应模型不匹配、核心离线、页面识别缺失及响应验证异常都只记录告警，不会阻断后续发送；正式请求仍会尝试按策略锁定模型。
