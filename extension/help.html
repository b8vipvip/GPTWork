快速开始 状态说明 自动验证 故障排查

1. 快速开始 Quick start

  1. 登录 GPTWork。 登录后扩展才会启用请求锁定能力。
  2. 打开“设置”。 选择允许使用的模型、推理强度和锁定策略。
  3. 确认“启用 GPTWork”已开启。 开启后，正式聊天请求会在发出前进入请求锁定检查。
  4. 打开 chatgpt.com 并正常聊天。 GPTWork 不要求你改用 API 或 Worker。
  5. 需要确认时点击“自动验证”。 GPTWork 会按当前策略收集可获得的请求与响应证据。

2. 设置模型和推理强度 Model & reasoning

在“设置”页面中配置允许的模型和推理强度。请求锁定以这里保存的策略为准；ChatGPT 页面上显示的模型文字只作为辅助信息，不能单独当作后端实际响应模型的证明。

建议：先只选择你真正希望使用的模型和推理强度，再进行自动验证，这样结果更容易判断。

3. 主界面状态说明 Status guide

本地核心 / Native Core

显示本地核心是否在线及版本。本地核心用于本地能力与响应证据相关功能。

请求锁定器 / Request interceptor

“已连接”表示当前 ChatGPT 标签页已挂接请求拦截能力，正式聊天请求会在发送前检查。

页面选择 / Page selection

来自 ChatGPT 页面 DOM 的辅助观察。显示“无 / None”不代表请求锁定失效。

响应确认 / Response evidence

显示当前能够取得的后端响应模型/推理证据。ChatGPT 未暴露字段时可能保持“无 / None”。

4. 自动验证怎么用 Auto verification

点击“自动验证”后，GPTWork 会使用当前锁定策略检查真实聊天链路，并在必要时自动完成程序能够执行的验证步骤。验证的目标是确认请求锁定是否生效，并尽可能取得后端响应证据。

  • 验证通过：取得了与策略一致的可信响应证据。
  • 部分确认/未完全确认：请求锁定可能已经执行，但 ChatGPT 当前没有暴露完整模型或推理元数据。
  • 模型不匹配：取得了明确的后端模型证据，且与允许策略不一致。

自动验证结果受 ChatGPT 当前网页协议和响应元数据可见性影响；“没有证据”与“明确证明使用了错误模型”是两种不同状态。

5. 常见问题 Troubleshooting

请求锁定器显示“未连接 / Detached”怎么办？

先确认当前标签页是 chatgpt.com，并刷新 ChatGPT 页面。随后重新打开 GPTWork 弹窗检查状态。如果仍未连接，可完全重启浏览器后再试。

本地核心显示“离线 / Offline”怎么办？

按弹窗中的本地核心安装提示完成安装或修复。安装完成后重新打开浏览器。正常情况下本地核心会自动连接并在断线后重试。

页面选择显示“无 / None”，是不是没锁住？

不是。页面选择只是 DOM 辅助观察；ChatGPT 页面结构变化、模型选择器未展开或未暴露推理字段时，都可能显示为空。应结合“请求锁定器”和“响应确认”判断。

响应确认一直是“无 / None”怎么办？

这通常表示当前响应没有暴露足够的可验证元数据。可以执行一次自动验证；如果仍无证据，GPTWork 会把它视为“未完全确认”，而不是自动判定成模型不匹配。

更新或异常后如何提供诊断信息？

通过顶部 GPTWork 模块导航进入“诊断日志”，导出运行日志后再用于排查。不要把账号密码、验证码等敏感信息写入问题描述。

6. 安全边界 Safety boundary

GPTWork 的目标是对 ChatGPT 网页正式聊天请求执行策略检查并收集可获得的验证证据。它不能强迫服务端暴露服务端本身没有返回的模型或推理字段，也不会把页面显示文字伪装成后端证明。
